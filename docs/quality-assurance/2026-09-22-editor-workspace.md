# 독립 레이어 편집 작업공간 검증

## 자동 검사

| 검사 | 실제 결과 |
|---|---|
| `bun run build` | `tsc --noEmit` 및 Vite 빌드 성공. 기존 종류의 500kB 청크 경고 존재, 메인 청크 약 773kB |
| `bun run lint` | 에러·경고 0 |
| `bun test src` | 9파일 53건 통과, 실패 0 |
| 마지막 슬라이드쇼 충돌 방지·상수 이동 후 `bunx tsc --noEmit`, 변경 4파일 eslint, `bun test src/store/editor-state.test.ts` | 모두 성공, 편집 상태 테스트 8건 통과. 전체 실행 때의 7건에 충돌 방지 1건 추가하여 고유 검증 54건 |
| `PATH="$HOME/.cargo/bin:$PATH" LIBOMP_PREFIX=/opt/homebrew/opt/libomp cargo test` (`src-tauri`) | 338건 통과, 실패 0. library ignore 3건과 binary별 ignore 각 1건은 기존 설정대로 미실행 |
| en/ko/ja 키를 재귀적으로 추출·정렬하여 비교 | 언어별 768키, 구조 차이 0; 소스의 정적 `t('…')` 참조 누락 0 |
| `git diff --check` | 공백 오류 없음 |

수정 전 실패를 직접 확인한 회귀: coalesced 배열 patch redo, 서로 다른 필드의 undo, 저장 응답 대기 중 추가 변경 flush. 수정 후 관련 테스트가 성공했습니다. 동일 코드·환경에서 성공한 전체 검사는 변경이 없는 범위에 재사용했습니다.

## 브라우저 실제 렌더·조작

Vite + Codex 내장 브라우저 1280×800, 실제 App·WebGL 렌더러를 사용했습니다. 임시 로컬 fixture가 Tauri IPC를 mock하고 1000×660 합성 사진과 텍스트/프레임 레이어를 제공했습니다. fixture는 제품 코드에 남기지 않습니다.

- 독립 사진 보정/레이어 편집 탭, 좌측 14개 도구, 상단 옵션, 우측 레이어·속성 패널 렌더 확인.
- 새 레이어를 추가하고 붉은 브러시로 드래그하여 실제 픽셀 변경을 관찰한 뒤 Undo로 제거 확인.
- 레이어 복제 → 이름 입력/Enter → 목록 반영 → V 이동 도구로 드래그. 원본 텍스트는 유지되고 복제 텍스트가 이동하며 Y 이동 값이 약 -11로 변경됨을 화면에서 확인.
- 이동 Undo/Redo, 사진 보정 탭 복귀, 손 도구 선택 확인. 브라우저 error 로그 0.
- 한글 줌 접근성 라벨 확인. 편집 준비 전 도구 비활성, l1 도착 후 활성 확인.

## 남은 실기기 검증 범위

| 조건 | 이번 실행에서 제외한 이유·위험 | 실행 시점 |
|---|---|---|
| 실제 macOS WKWebView에서 RAW·애니메이션 왕복, Space 팬·클론·블러, 변형/크롭을 결합한 장시간 편집 | 브라우저 UI 검증은 합성 이미지·IPC mock 사용. 네이티브 WebView와 실제 디코드 타이밍 차이가 남음 | 다음 네이티브 앱 실사용/릴리스 검증 |
| 실제 디스크 저장 실패·내보내기 중 디스크 부족·창 닫기·파일 감시 순서 경쟁 | 사용자 파일·디스크를 고의로 손상하거나 가득 채우지 않음. 일부는 제어 흐름 대조 및 저장 IPC 회귀 테스트로 검증 | 격리된 테스트 폴더와 실패 주입 환경에서 릴리스 전 |
| WebGPU 수치 패리티 하니스 | 이번 변경은 WGSL/GLSL 수식과 Rust 디코더를 수정하지 않음. 기존 성공 결과 재사용; Canvas2D 레이어와 별도 | 셰이더 변경 또는 WebGPU 릴리스 검증 |
| CPU 폴백·애니메이션의 레이어 편집 | 현재 엔진에서 지원하지 않아 진입/조작 제한. 기존 저장 데이터 스키마 변경 없음 | 해당 렌더 경로에 레이어 합성을 구현할 때 |

레이어 미리보기는 벡터/드로잉 내용의 축소본입니다. 원본 사진을 샘플링하는 복제·블러 전용 레이어는 사진을 읽지 않는 썸네일에 나타나지 않을 수 있으며 실제 캔버스에는 합성됩니다.

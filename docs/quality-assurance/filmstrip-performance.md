# 필름스트립 성능 실측 체크리스트 (아틀라스 도입 판단 근거)

> 아틀라스(썸네일 텍스처 패킹)는 "실측에서 병목 확인 전 미착수"가 확정 결정이다(acknowledge/decisions.md).
> 이 문서는 그 "실측"을 수행하는 절차다. 스크롤 fps 확인은 실화면이 필요해 **사용자 재석 시** 수행한다.

## 배경 (현 구현)

- 필름스트립·그리드는 DOM `<img src=aether l0>` + react-virtual 가상화(overscan 8/4)다. GL 텍스처가 아니므로 아틀라스의 전제(드로우콜 병합)가 바로 적용되지 않는다.
- aether 응답은 `Cache-Control: no-cache`라 **overscan 밖으로 나갔다 돌아온 셀은 l0을 재fetch + JPEG 재디코드**한다. 병목이 있다면 이 지점이다(디스크 캐시 히트라 백엔드 비용은 낮고, 프론트 디코드·GC가 관건).

## 측정 절차

- [ ] 1000장 이상 디렉토리를 연다 (tier2 생성 스크립트 또는 실사진 폴더).
- [ ] Perf 오버레이(⌥⌘P 계열, PerfOverlay.tsx)를 켜고 필름스트립을 끝까지 왕복 스크롤한다.
  - 기대: 55fps 이상 유지. 미달이면 병목 후보.
- [ ] devtools Network에서 `pixels/*/l0` 요청 수를 관찰한다.
  - 같은 셀 왕복 시 재요청이 대량 발생하는지(=재디코드 비용) 확인.
- [ ] 그리드 뷰(전체 화면 셀 수십 개)에서 동일 왕복.

## 판단 기준

| 결과 | 조치 |
|------|------|
| 왕복 스크롤 55fps 이상 | 아틀라스 불요 — 결정 유지, 이 문서에 결과 기록 후 종결 |
| fps 미달 + 재fetch 다량 | 1차: l0 응답에 immutable 캐시 헤더(rev 쿼리가 이미 캐시버스터) 검토. 2차: 아틀라스 계약 작성 |
| fps 미달 + 재fetch 소량 | DOM/레이아웃 병목 — 아틀라스와 무관, 별도 프로파일 |

# 다국어 (i18n)

## 구조

언어 파일은 전부 `src/i18n/` 한 곳에 모여 있다.

```
src/i18n/
├── i18n.ts   # i18next 초기화 · AppLanguage 타입 · 시스템 언어 감지
├── en.ts     # 영어 (기준 카탈로그 — 키 구조의 단일 출처)
├── ko.ts     # 한국어
└── ja.ts     # 일본어
```

현재 지원: 한국어 · English · 日本語 (+ 시스템 자동). 시스템 언어가 셋에 없으면 영어로 폴백한다.

## 번역 PR 기여 방법

1. **기존 언어 수정**: 해당 파일(`ko.ts`/`en.ts`/`ja.ts`)의 값만 고친다. 키를 추가·삭제·이동하지 않는다.
2. **새 언어 추가** (예: 중국어 `zh`):
   - `en.ts`를 복사해 `src/i18n/zh.ts` 생성 후 값을 번역한다. **키 구조는 en.ts와 완전히 일치**해야 한다.
   - `i18n.ts`에서 (a) import 추가, (b) `AppLanguage`/`UiLanguage`에 `'zh'` 추가, (c) `resources`에 등록, (d) `resolveLanguage`에 시스템 감지 분기 추가.
   - `src/store/settings.ts`의 `isLanguage`에 `'zh'` 추가.
   - `src/components/settings/SettingsDialog.tsx`의 언어 Segmented에 옵션 추가 + 각 언어 파일에 `settings.languageZh` 라벨 추가.
3. **검증** (PR 전 필수):
   ```sh
   bun -e "
   const { en } = await import('./src/i18n/en.ts')
   const { zh } = await import('./src/i18n/zh.ts')
   const flat = (o, p = '') => Object.entries(o).flatMap(([k, v]) => (typeof v === 'object' && v !== null ? flat(v, p + k + '.') : [p + k]))
   const a = new Set(flat(en)), b = new Set(flat(zh))
   console.log('missing:', [...a].filter((k) => !b.has(k)))"
   bun run typecheck
   ```

## 규칙

- `{{count}}` 같은 보간 변수는 그대로 유지한다.
- 단축키 표기(⌘ ⇧ ⌥ 등)와 포맷 특수문자를 유지한다.
- 사진/현상 도구 표준 용어를 따른다 (Lightroom 해당 언어판 용어 준거).
- 새 UI 문자열은 하드코딩하지 않고 세 카탈로그 모두에 키를 추가한다.
